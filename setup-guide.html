איך מקימים טופס אפיון משלכם

עותק עם הלוגו שלכם והמייל שלכם, כתובת אינטרנט משלכם, והתשובות מגיעות ישר לתיבה שלכם.

זמן הקמה ~20 דקות עלות 0 ₪ נדרש חשבון GitHub

לכל אנליסט טופס נפרד. אם שלושה יעבדו על אותו טופס, התשובות של כולם יגיעו לאותה תיבה. אז כל אחד מקים עותק אחד, פעם אחת, ואחר כך שוכח מזה.

צריך חשבון GitHub. אין דרך לעקוף את זה, וזה גם לא באמת חסם: ההרשמה חינמית ולוקחת שתי דקות. בסוף המדריך יש סעיף שמסביר בדיוק מה פומבי כאן ומה לא, כי זו השאלה הראשונה שכולם שואלים.

ששת השלבים

1

חשבון GitHub וריפו חדש

  1. נרשמים ב-github.com/signup.
  2. לוחצים New ויוצרים ריפו חדש. שם טוב: project-brief.
  3. משאירים אותו Public.
למה Public

GitHub Pages, השירות שיהפוך את הקובץ לכתובת אינטרנט, לא עובד על ריפו פרטי בחשבון חינמי. מה שיהיה פומבי זה קובץ הטופס עצמו, לא התשובות. פירוט מלא למטה.

2

מעלים את הקבצים

מקבלים מאורי את index.html. בריפו החדש: Add file → Upload files, גוררים את הקובץ, Commit changes.

אם יש לכם לוגו, מעלים גם אותו באותה דרך. שמרו אותו בשם logo.png, PNG עם רקע שקוף, ברוחב 400 פיקסלים בערך. תמונה של 4 מגה סתם מאטה את הטופס לפונה.

3

מדליקים את האתר

  1. בריפו: Settings → Pages.
  2. תחת Source בוחרים Deploy from a branch.
  3. תחת Branch בוחרים main ואת התיקייה / (root), ואז Save.

אחרי דקה או שתיים הכתובת תופיע באותו עמוד, בצורה https://SHEM-MISHTAMESH.github.io/project-brief/. זו הכתובת שתשלחו ליחידות. שמרו אותה.

4

חשבון EmailJS

EmailJS לוקח את מה שמולא בטופס ושולח לכם אותו במייל. חינמי עד 200 מיילים בחודש.

  1. נרשמים ב-emailjs.com.
  2. Email Services → Add New Service, בוחרים Gmail או Outlook, מחברים את חשבון המייל שממנו יישלחו ההודעות. בסוף מקבלים Service ID.
  3. Email Templates → Create New Template, וממלאים כך:
שדה בתבניתמה לכתוב בו
To Email{{to_email}}
Reply To{{from_email}}
Subjectאפיון חדש מ-{{from_unit}}
Content{{message}}
כאן נופלים

{{to_email}} בשדה To Email הוא מה שגורם לתבנית לעבוד לכל אחד. אם תכתבו שם כתובת מייל קשיחה, הטופס ישלח לשם, לא לכם, ולא תהיה שום הודעת שגיאה שתסביר למה.

{{from_email}} בשדה Reply To אומר שלחיצה על "השב" במייל תגיע לאדם שמילא את הטופס. בלי זה תשלחו תשובה לעצמכם.

  1. שומרים, ומקבלים Template ID.
  2. Account → General: משם לוקחים את ה-Public Key.
  3. Account → Security: מדליקים Allow list ומוסיפים את הדומיין SHEM-MISHTAMESH.github.io. בלי זה, מי שמעתיק את הקוד שלכם יכול לשלוח מיילים על חשבון המנה שלכם.
5

פותחים את index.html בריפו ולוחצים על העיפרון. קרוב לסוף הקובץ יש בלוק אחד מסומן, וזה כל מה שצריך לגעת בו:

שני דברים ששווה להתאים

logo נשאר ריק ("") אם אין לכם קובץ לוגו. אז יוצג השם שלכם כטקסט, והטופס נראה תקין ולא שבור.

sourceSystems היא הרשימה שמופיעה בשאלה "מאיפה הנתונים מגיעים?". ערכו אותה למערכות שאתם באמת עובדים איתן. אנליסט באגף כספים ואנליסט במדור בחינות עובדים מול מערכות אחרות לגמרי, וכשהרשימה מדויקת הפונה מסמן במקום לכתוב, ואתם מקבלים תשובה שאפשר לעבוד לפיה.

Commit changes, ואחרי דקה השינוי באוויר.

6

בודקים שזה עובד

נכנסים לכתובת שלכם, ממלאים את הטופס בנתונים מומצאים, ושולחים. המייל צריך להגיע תוך שניות.

אם לא הגיע: פתחו את הכתובת בכרום, לחצו F12, ותסתכלו על הלשונית Console. שגיאה של EmailJS תופיע שם עם הסבר. ברוב המקרים הבעיה אחת מהשלוש: מפתח שהועתק עם רווח מיותר, שדה To Email שאינו {{to_email}}, או Allow list שמוגדר לדומיין אחר.

אבטחת מידע

הריפו פומבי, וזו השאלה הראשונה שעולה. בפירוט:

מה כל אחד יכול לראות

את קובץ ה-HTML, את הלוגו, ואת מפתח ה-EmailJS הפומבי. המפתח הזה נקרא Public Key כי הוא נועד לשבת בקוד של דף אינטרנט. הוא מזהה את החשבון ולא נותן גישה אליו, ואי אפשר לקרוא איתו שום מייל ששלחתם או קיבלתם.

מה אף אחד לא יכול לראות

את התשובות. אף מילוי של הטופס לא נשמר בריפו ולא ב-GitHub. מה שמולא נשלח דרך EmailJS ישר לתיבה שלכם ונעלם מהדף. אין מסד נתונים, אין ארכיון, אין לוג.

מה כן צריך לעשות

להדליק את ה-Allow list בשלב 4. זה מה שמונע ממישהו לקחת את הקוד שלכם ולשלוח מיילים על חשבון המנה החודשית שלכם.

מה לא לעשות

  • לא להעלות לריפו קבצי נתונים אמיתיים. שום אקסל של סטודנטים, שום ייצוא ממערכת, שום .db. הריפו מכיל קובץ טופס ולוגו, וזה הכל.
  • לא להשתמש בטופס לאיסוף מידע אישי. הטופס שואל את היחידה מה הצורך שלה, הוא לא מבקש ממנה נתונים. אם פונה מתחיל להדביק תעודות זהות או ציונים בשדה טקסט, עצרו אותו והעבירו את זה לערוץ מאובטח. המילוי עובר בדרכו אליכם דרך שרת של EmailJS, וזה בסדר לתיאור צורך, לא לנתונים.

שאלות שחוזרות

אפשר להוסיף או לשנות שאלות?

כן, זה HTML רגיל. רק שימו לב לדבר אחד: לכל שדה יש name, ובתוך הפונקציה buildSummary יש מילון שמתרגם כל name לכיתוב בעברית. שדה שנוסיף בלי לרשום אותו במילון פשוט לא יופיע במייל, בלי שום הודעת שגיאה. זו הטעות הכי נפוצה בקובץ הזה.

מה קורה אם עוברים את 200 המיילים בחודש?

EmailJS מפסיק לשלוח עד תחילת החודש הבא. לטופס אפיון שנשלח לכמה יחידות בשנה זה רחוק מלהיות בעיה. אם אתם מתקרבים למגבלה, כנראה שהטופס משמש למשהו אחר ממה שהוא נבנה בשבילו.

אפשר לשנות את העיצוב?

כן. כל ה-CSS יושב בראש הקובץ, והצבעים מוגדרים כמשתנים תחת :root. שינוי של --color-accent מחליף את צבע ההדגשה בכל הטופס.

איך מקבלים את כל התשובות במקום אחד ולא כמיילים בודדים?

אין תשובה טובה לזה בגרסה הזאת. אם תגיעו למצב שהטופס נשלח לעשרות יחידות ואי אפשר לעקוב במייל, דברו עם אורי, כי זה כבר צריך פתרון אחר.
